# 裁判系统硬件与协议学习文档

## 一、裁判系统全量硬件清单

裁判系统的核心硬件模块共 **10 类**，涵盖供电、感知、通信、状态显示等全流程功能：

- 裁判系统主控模块
- 电源管理模块
- 装甲模块
- 相机图传模块（发送端 + 接收端）
- 定位模块
- 场地交互模块
- 灯条模块
- 超级电容管理模块 CM01
- 测速模块
- 场地交互卡（IC 卡，配合场地交互模块使用）

---

## 二、地面兵种（如步兵、英雄机器人）必备裁判系统硬件及作用

地面兵种需搭载 **“核心控制 + 基础感知 + 状态反馈 + 供电保障”** 类模块，以下为必备清单及核心作用：

### 1. 裁判系统主控模块（核心必备）
**作用**：裁判系统的 “大脑”，监控整个系统运行状态，集成人机交互、无线通信、状态显示功能，协调所有模块数据互通。

### 2. 电源管理模块
**作用**：
- 为底盘、云台、发射机构提供 **3 路独立 24V 直流供电**，同时输出 5V、12V、24V 电源供其他裁判模块使用；
- 实时监测各供电通道的电流、电压，计算功率，支持按服务器指令控制电源通断；
- 具备通信转发功能，将各模块数据包转发至目标模块，通过 **“User 接口”** 输出裁判系统信息供参赛队使用。

### 3. 装甲模块
**作用**：机器人的 **“伤害感知单元”**，安装于机器人外侧，专门检测被弹丸攻击、碰撞的情况，为血量扣除、状态判定提供依据。

### 4. 灯条模块
**作用**：机器人的 **“状态可视化单元”**，通过灯条亮灭、颜色变化，直观显示机器人当前剩余血量及所处状态（如正常、低血、无敌等），方便参赛队和裁判实时观察。

### 5. 相机图传模块（仅需发送端）
**作用**：
- 发送端安装在机器人上，负责实时采集高清图像，通过无线传输至接收端；
- 为参赛队提供机器人第一人称视角，支持多套模块同时工作，保障低延迟、高帧率的画面反馈（接收端连接电脑，无需安装在机器人上）。

### 6. 定位模块
**作用**：
- 与场地基站通信实现精准定位，为比赛地理围栏提供判定依据；
- 定位数据是比赛客户端小地图的核心来源，同时通过电源管理模块的 **“用户接口”** 输出，供参赛队用于路径规划、目标定位。

## 三、地面兵种可选裁判系统硬件及适用场景

以下模块根据机器人功能配置（如是否带发射机构、是否用超级电容、是否需场地交互）选择搭载：

### 1. 测速模块（发射机构时必备）
**作用**：内置传感器，实时测枪管弹丸的速度和发射频率，通过 **CAN 接口** 按裁判协议将数据上报服务器用于违规判定。

### 2. 超级电容管理模块 CM01（使用超级电容时必备）
**作用**：监测超级电容模组的容值、实时电压和剩余容量，搭配主控模块和电源管理模块使用，保障超级电容安全稳定工作。

### 3. 场地交互模块（需读写 IC 卡时搭载）
**作用**：采用 **13.56MHz 低频信号**，支持读写 **ISO15693** 标准的 IC 卡（配合场地交互卡使用），有效探测距离 100mm±5%；  
集成 CAN 通信和多状态指示灯，实现机器人与场地 IC 卡的交互（如获取任务、打卡等）。

### 4. 场地交互卡（配合场地交互模块使用，无需安装在机器人上）
**作用**：符合 ISO15693 协议的 IC 卡，放置于场地指定位置，供机器人的场地交互模块读写数据，实现场地交互功能。

---

## 四、核心总结

- **必备模块**：主控模块 + 电源管理模块 + 装甲模块 + 灯条模块 + 相机图传发送端 + 定位模块，覆盖地面兵种基础运行、伤害感知、状态显示、定位导航核心需求；
- **可选模块**：根据功能扩展（发射机构→测速模块、超级电容→CM01 模块、场地交互→场地交互模块）灵活搭配；
- 所有模块需通过主控模块和电源管理模块实现数据互通、供电保障，形成完整的裁判系统闭环。

## 串口协议

### 1. 基础通信配置
| 参数 | 常规链路 | 图传链路 |
|------|----------|----------|
| 波特率 | 115200 | 921600 |
| 数据位 | 8 位 | 8 位 |
| 停止位 | 1 位 | 1 位 |
| 校验位 | 无 | 无 |
| 硬件流控 | 无 | 无 |

**数据性能要求**：
- 正常延迟 ≤ 130ms，恶劣环境 ≤ 200ms
- 丢包率 ≤ 3%

### 2. 帧格式规范
```
帧结构：
[ 帧头（5字节） ] + [ 命令ID（2字节） ] + [ 数据段（n字节） ] + [ 帧尾（2字节，CRC16校验） ]
```
- **帧头（frame_header）**：包含起始字节（SOF = 0xA5）、数据长度、包序号、CRC8 校验
- **核心特点**：整包 CRC16 校验 + 帧头 CRC8 校验，双重保障数据完整性

### 3. 三大数据链路
| 链路类型 | 数据流向 | 核心命令码 | 频率限制 |
|----------|----------|------------|----------|
| 常规链路 | 服务器 ↔ 机器人、机器人 ↔ 机器人 | 比赛状态（0x0001）、血量数据（0x0003）、机器人性能数据（0x0201） | 最高 30Hz |
| 图传链路 | 选手端 ↔ 机器人、自定义控制器 ↔ 机器人 | 键鼠遥控（0x0304）、自定义数据交互（0x0302/0x0309） | 最高 50Hz |
| 雷达无线链路 | 信号发射源 → 雷达 | 对方机器人位置（0x0A01）、对方血量（0x0A02） | 最高 10Hz |

### 4. 关键命令码分类（常用）

#### （1）比赛全局状态类（服务器 → 全体机器人）
| 命令码 | 用途 | 发送频率 |
|--------|------|----------|
| 0x0001 | 比赛状态（比赛类型、剩余时间、时间戳） | 1Hz |
| 0x0002 | 比赛结果（红 / 蓝方胜利、平局） | 比赛结束触发 |
| 0x0003 | 己方机器人 + 前哨站 + 基地血量 | 3Hz |

#### （2）机器人本地数据类（主控 → 机器人）
| 命令码 | 用途 | 发送频率 |
|--------|------|----------|
| 0x0201 | 机器人性能数据（ID、血量、热量上限、功率上限） | 10Hz |
| 0x0202 | 功率热量数据（缓冲能量、17mm/42mm 发射机构热量） | 10Hz |
| 0x0203 | 机器人位置（X/Y 坐标、朝向角度） | 1Hz |

#### （3）飞镖专项类（服务器 → 飞镖机器人）
| 命令码 | 用途 | 发送频率 |
|--------|------|----------|
| 0x0105 | 飞镖发射信息（剩余时间、击中目标、选定目标） | 1Hz |
| 0x020A | 飞镖选手端指令（发射站状态、目标切换时间） | 3Hz |

#### （4）遥控与交互类（选手端 → 机器人）
| 命令码 | 用途 | 发送频率 |
|--------|------|----------|
| 0x0304 | 键鼠遥控数据（鼠标移动、按键状态） | 30Hz |
| 0x0303 | 小地图点击指令（目标坐标、操作类型） | 触发式发送（触发后重复 5 次） |

## 三、自定义客户端协议

### 1. 通信基础
- **传输协议**：MQTT（发布 / 订阅模式）
- **服务器地址**：IP = `192.168.12.1`，端口 = `3333`
- **数据格式**：Protobuf v3 序列化二进制流（支持多语言解析）
- **图传码流**：UDP 监听端口 `3334`，HEVC 编码，含帧编号、分片信息

### 2. 核心指令（常用）
| 指令名 | 用途 | 频率 | 数据流向 |
|--------|------|------|----------|
| GameStatus | 同步比赛全局状态（局数、得分、剩余时间） | 5Hz | 服务器 → 客户端 |
| GlobalUnitStatus | 同步基地、前哨站、机器人血量 / 弹量 | 1Hz | 服务器 → 客户端 |
| RobotDynamicStatus | 机器人实时数据（血量、热量、剩余弹量） | 10Hz | 服务器 → 客户端 |
| RemoteControl | 传输键鼠输入与自定义数据 | 75Hz | 客户端 → 服务器 |
| DartCommand | 飞镖控制指令（目标选择、闸门开关） | 1Hz | 客户端 → 服务器 |

## 四、关键辅助规范

### 1. CRC 校验
- **CRC8**：用于帧头校验，多项式 **G(x) = x⁸ + x⁵ + x⁴ + 1**
- **CRC16**：用于整包数据校验，初始化值 **0xFFFF**（提供完整代码示例）
- 此处并未细看，仅为了解
### 2. ID 编号规则（核心标识）
#### 概括常见的兵种编号
##### 机器人 ID
| 红方 ID | 兵种 | 蓝方 ID | 兵种 |
|---------|------|---------|------|
| 1 | 英雄 | 101 | 英雄 |
| 3~5 | 步兵 | 103~105 | 步兵 |
| 7 | 哨兵 | 107 | 哨兵 |
| 8 | 飞镖 | 108 | 飞镖 |

##### 选手端 ID
- 红方：`0x0101` ~ `0x0106`
- 蓝方：`0x0165` ~ `0x0169`
- 裁判服务器：`0x8080`

---

## 五、核心特点总结


1. **高可靠性**：
   - 双重 CRC 校验（CRC8 + CRC16）
   - 固定频率发送
   - 重复包机制（如 `0x0303` 指令触发后重复发送 5 次）

2. **功能专项化**：
   - 飞镖、哨兵、雷达均有专属命令码，适配不同兵种需求
